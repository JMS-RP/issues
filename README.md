# JMS-RP Community Issue Tracker

This is the public issue tracker for JMS RP.

It is open to players, testers, staff, developers, and anyone who wants to report a problem or suggest an improvement to the JMS RP experience.

## What belongs here

- Bugs and broken functionality
- Missing or unfinished features
- UI and usability feedback
- Gameplay and balance suggestions
- Performance problems
- Documentation issues
- Reproducible integration or compatibility problems

This repository is an issue tracker, not the source code repository for JMS RP resources.

## Before opening an issue

1. Search existing open and closed issues for duplicates.
2. Confirm the problem still exists on the latest available server/resource build.
3. Identify the script, feature, location, command, item, or UI involved.
4. Record clear reproduction steps.
5. Include screenshots, video, F8 output, or server-console output where useful.
6. Remove passwords, tokens, IP addresses, private URLs, player identifiers, and other sensitive information before posting.

## Reporting a bug

A useful bug report should explain:

- Which script or feature is affected
- What you expected to happen
- What actually happened
- The exact steps needed to reproduce it
- Whether it happens every time or intermittently
- The server/build/environment used
- Any relevant evidence

The bug-report form will guide you through these details.

## Suggesting an improvement

A useful suggestion should explain:

- What problem or limitation exists today
- What change you propose
- Why the change would improve gameplay, usability, roleplay, or reliability
- Which players, jobs, scripts, or systems it affects
- Any alternative solutions you considered

Suggestions are feedback for the JMS RP team and are not guarantees of implementation.

## Security and abuse reports

Do not publish credentials, private data, or immediately usable exploit instructions in a public issue.

If you believe you have found a security vulnerability, economy exploit, permission bypass, duplication issue, or other abuse path, contact JMS RP staff privately through the official [JMS RP Discord](https://discord.gg/hPBSaBggJ9) and clearly say that the report is security-sensitive.

## Issue labels

Labels are used to organise reports by type, status, priority, and affected area. New reports normally begin in triage while the team confirms scope and reproduction.

Common statuses include:

- status: triage — newly received and awaiting review
- status: confirmed — reproduced or accepted for investigation
- status: needs info — more details are required
- status: in progress — actively being worked on

Labels are created and maintained automatically by this repository's label workflow.

## Community support

For quick questions, account-specific help, or live troubleshooting, use the [JMS RP Discord](https://discord.gg/hPBSaBggJ9). Public issues are visible to everyone and should contain only information you are comfortable sharing publicly.
